# Presentation → PsychoPy

Produce a small, checkable manifest **before** any code. Errors caught in a
100-line YAML are cheap; the same errors in a 600-line script are not.
One paradigm SET per session.

> ## ⚠️ This workflow cannot currently run
>
> It depends on tooling that is **not present in this repository**:
> `probe.sh`, `make_prompts.sh`, `target.env`, `check_runs.sh`, `lint_style.sh`
> and `template/paradigm_template.py`. They were part of the retired Claude-era
> `Agent/05_Paradigm/` layout.
>
> The probe is not optional decoration. It measures trial counts, block order,
> response-code mapping and **missing stimulus files** from the real run logs.
> Reading those off the PCL by hand is exactly what it exists to prevent, and a
> paradigm converted from a miscounted block structure is worse than no
> conversion, because it looks finished.
>
> If the source paradigm is Presentation: report that the tooling is missing and
> stop. To restore it, look for the deletion commit:
> `git log --diff-filter=D -- 'Agent/05_Paradigm/*'`
>
> The passes below are kept as the specification of what to restore, and are
> accurate about the method — only the script paths are dead.

## Configure once per paradigm

Paths live in `Agent/05_Paradigm/target.env` (data, one block per paradigm) —
never typed into prompts by hand:

```bash
./Agent/05_Paradigm/make_prompts.sh --list    # what paradigms exist
./Agent/05_Paradigm/make_prompts.sh --check   # verify configured paths
```

## Pass 0 — Probe (measure before reading)

```bash
./Agent/05_Paradigm/probe.sh
```

Writes `Agent/05_Paradigm/probes/<TAG>_probe.md`: trial counts, block order,
stimuli per block, response-code mapping, realised durations, **missing stimulus
files**, directory pollution, absolute paths. It is authoritative. Never escalate
a question it answers. **Missing stimuli → STOP and report. Do not convert.**

No run logs (common for short versions) → counts must come from the PCL; state
your reasoning and expect more open questions. Never inherit counts from a
full-length version.

## Pass 1 — Inventory → manifest (no code)

Read the `.exp` **and every `sce/*.sce` it references** — the logic lives there.
List the `Stimuli/**` tree. Write `Agent/05_Paradigm/manifests/<TAG>.yaml`:

```yaml
paradigm: <TAG>
source: {exp: <path>, scenarios: [<sce paths>], stimuli_root: <path>}
display: {background_rgb: [r, g, b], font_size_px: <n>, units: pix}
response: {keys: [...], quit_key: escape, timeout_ms: <n or null>}
blocks:  [{name: <>, type: <>, n_trials: <n>, randomize: <bool>}]
events:  [{id: <>, kind: blank|bitmap|text|response, asset: <>, duration_ms: <n or null>}]
stimuli: [{ref: <as written>, path: <resolved>, exists: true|false}]
unresolved: []        # referenced but not on disk — must be empty
open_questions: []    # ambiguities you refused to guess
```

Durations in **ms as written**. Every stimulus verified on disk, matched
case-sensitively. Then STOP.

## Pass 2 — Human review

The human checks `unresolved:` and `open_questions:` are empty, counts are sane,
two durations spot-checked against the `.sce`. No Pass 3 until the manifest is clean.

## Pass 3 — Generate from the manifest

- The manifest is the source of truth; if it disagrees with the `.sce`, stop and ask.
- Copy the setup block from `Agent/05_Paradigm/template/paradigm_template.py`
  (skill `psychopy-house-style`).
- If a human-made PsychoPy version of this paradigm exists anywhere under
  `Projects/*/paradigm/psychopy/`, read it first and match its structure; write
  `<name>_generated.py` beside it — **never overwrite a reference file**.
- Convert ms → s here, with a comment saying so.
- No parallel-port / trigger code. A `port_code` may be logged, sent nowhere.
- Provenance header:
  ```python
  # AUTO-GENERATED by BEEHub converter -- DO NOT EDIT BY HAND
  # source: <manifest path>
  # model:  <provider/model of this OpenCode session>   generated: <UTC timestamp>
  ```

## Pass 4 — Gate

```bash
python3 Agent/tools/check_paradigm.py "<generated file>" --generated --launch
```

Lint → compile → headless launch. On failure fix the real cause and re-run. Never
report success while failing. The gate proves it *launches*, not that trials are
right — the human still diffs against any reference and clicks through.

## Decisions that are never yours

Nominal vs empirical (log-median) timing when the original was scanner-locked;
the intent behind deliberate-looking oddities; instruction wording when the
response device changes. Put them in `open_questions`.
