## ⚠️  SHOULD FIX

### B1. `bids_data/` missing BIDS metadata files

Layout requires `participants.tsv`, `participants.json`, `README.md`,
`task-gonogo_beh.json` at the top of `bids_data/`. None exist:

```
$ ls Projects/MT/bids_data/
dataset_description.json  sub-001  sub-002  ... sub-026
```

Calibration: `Projects/OLM/bids_data/` has `participants.tsv` and
`task-OLM_beh.json` but is also missing `participants.json` and `README.md`
— so OLM would trip this check too. The `participants.tsv` +
`task-gonogo_beh.json` gap is specific to MT; the other two are a
repository-wide convention question for the human to settle.

### B2. Hardcoded absolute Windows paths in `code/`

```
$ grep -nE 'C:/' Projects/MT/code/*.R
code/2. ER_RT.R:17:  file_path <- "C:/1_DevuMahesan_Data/..."
code/2. ER_RT.R:18:  out_xlsx  <- "C:/1_DevuMahesan_Data/..."
code/3. Kinematics.R:46:  file_path   <- "C:/1_DevuMahesan_Data/..."
code/3. Kinematics.R:47:  output_xlsx <- "C:/1_DevuMahesan_Data/..."
```

These scripts cannot run on any machine other than the original analysis
workstation, and any path change there breaks them silently. (They are not
declared in `derivations.json` — only `1. compute_stopping.R` is — so they do
not block the derivation contract, but they will block any future derivation
that wraps them.)

### B3. `MT_description.json` → `derivations` block does not match
    `code/derivations.json`

```
$ python3 -c "import json;print(json.load(open('Projects/MT/MT_description.json'))['derivations'])"
[{'label': 'scored', 'script': 'code/compute_stopping.R',
  'input': 'bids_data/sub-*/ses-*/beh/*_task-gonogo_beh.tsv', ...}]
$ python3 -c "import json;print(json.load(open('Projects/MT/code/derivations.json')))"
[{'name': 'scored', 'script': 'code/1. compute_stopping.R',
  'input': 'bids_data', 'output': 'derivatives/scored',
  'params': 'code/scored_params.json', ...}]
```

The description JSON says the script is `code/compute_stopping.R`, which
does not exist (the real file is `code/1. compute_stopping.R`). The
authoritative `code/derivations.json` is correct — `run_derivation.py MT
--dry-run` resolves it and reports `1 derivation(s), 0 failed` — so this
is a description drift, not a pipeline failure. Fix the `derivations`
block in `MT_description.json` to match `code/derivations.json`.

### B4. 40+ untracked / 530 deleted files in git under `Projects/MT`

```
$ git status --short Projects/MT/ | wc -l
570+
$ git status --short Projects/MT/ | grep -c '^??'   # untracked, includes:
    agent_out/*.md, bids_data/sub-002/, sub-004/, sub-025/,
    code/*.original, code/derivations.json, code/scored_params.json,
    derivatives/scored/, literature/*, paradigm/psychopy/*
$ git status --short Projects/MT/ | grep -c '^ D'   # deleted, includes:
    bids_data/*/ses-*/beh/*_task-gonogo_beh.tsv (all 50),
    bids_data/*/ses-*/beh/*_task-gonogo_beh.json,
    agent_out/*.txt, top-level MT_data.json / MT_overview.html
```

The project is in a mid-migration state: the old run-grain TSVs were deleted
and the new session-grain TSVs are not yet tracked. Nothing here is a
layout violation per se, but until this is committed the project does not
represent its current state in version control, and the 50 deleted
`_beh.tsv` files cannot be recovered from git if the working tree is
wiped before a commit.

produced scripts are exempt.)

### B6. `MT_description.json` → `derivations` omits the `kinematics`
    derivative that exists on disk

```

$ git status --short Projects/MT/derivatives/kinematics/ | head -3
 D Projects/MT/derivatives/kinematics/dataset_description.json
 D .../sub-001_ses-01_task-gonogo_desc-kinematics_beh.tsv
```

`derivatives/kinematics/` (with its own `dataset_description.json` and
per-subject TSVs) is tracked in git but deleted in the working tree and

is a live derivative, re-declare it in `code/derivations.json` and
restore the files; if it was superseded, the deletion should be
committed deliberately, not left in a 530-file pending state (see B4).

### N2. `outcome_measures` role mix

`MT_description.json` declares:

| id | column | role |
|---|---|---|
| RT | rt_combined | primary |
| ACCURACY | accuracy | secondary |
| NOGO_STOP_TIME | nogo_stop_time | **undecided** |

`suggest_outcomes.py MT` agrees on the three candidate columns. The
`undecided` entry means the project is reported but withheld from
cross-project comparison for that measure until a PI decision — that is
the correct, honest state, not a defect. (An open question already in

to match APPL/OLM.)

### N3. Paradigm gate false positives

`python3 Agent/tools/check_paradigm.py Projects/MT/paradigm/psychopy/
go_nogo_dm.py` reports two missing assets:

```
temp_go_nogo_shuffled.xlsx
temp_nogo_shuffled.xlsx
```

These are false positives: the strings appear as f-string literals in
`os.path.join(data_folder, f"temp_{block_type}_shuffled.xlsx")` and are
created at runtime by the script itself, not read from disk. The script
compiles, its real assets (`.xlsx` condition files, `.PNG` slides) are
present, and the gate passes.
